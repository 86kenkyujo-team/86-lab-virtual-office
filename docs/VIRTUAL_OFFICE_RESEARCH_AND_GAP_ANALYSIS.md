# 86研究所 仮想オフィス 現状整理と改善候補

作成日: 2026-05-27

## 結論

現状のシステムは「バーチャルオフィス風の在籍管理MVP」としては成立している。QR入室、リモート入室、退室、状態変更、オフィスマップ、リモートエリア、履歴、タイムライン、Supabase移行前提のデータ構造まで揃っている。

一方で、既存のバーチャルオフィス製品と比べると、まだ「会話が始まる」「予定と連動する」「席や会議室を予約する」「通知する」「管理する」「分析する」という層が足りない。今後の方向性としては、ゲーム的な自由移動を急ぐより、86研究所向けには以下の順で厚くするのがよい。

1. 在籍データの信頼性と見やすさを上げる。
2. 話しかけやすさ、通知、簡易チャットを足す。
3. カレンダー、予定、会議中、集中中を連動する。
4. 座席、部屋、フロアの管理UIを作る。
5. Supabase Auth / Realtime / 権限管理に移す。
6. 利用状況とオフィス活用を分析できるようにする。

## 現状の実装棚卸し

### できていること

- `server.mjs` で静的配信と `/api/state`、`/api/health`、`/api/presence` を提供している。
- `data/presence-db.json` をローカルJSON DBとして使い、Supabase未設定でも動作確認できる。
- `api/_lib/store.js` はローカルJSONとSupabase REST/RPCの両方に対応している。
- `supabase/schema.sql` には `offices`、`profiles`、`attendance_sessions`、`current_presence`、`presence_events` がある。
- QR入室とリモート入室を `entryMethod` で分けて履歴に残している。
- オフィス勤務者だけをオフィスマップに表示し、リモート勤務者はリモートエリアに表示している。
- 作業中、離席、会議中のステータス切替ができる。
- PCでは左ナビ、中央マップ、右プレゼンスパネル。スマホでは1カラムと下部ナビになる。
- `public/assets/office-assets.json` でPC/スマホ背景、座標、メンバー別スプライトを管理している。
- 30秒ポーリングで状態を再取得している。
- `npm test` と `npm run build` は通る。

### 現状の気になる点

- 本番運用のログイン/本人確認がなく、操作ユーザー切替で誰の状態でも変更できる。
- QRプレビューは実QRコードではなく、スキャン可能性が弱い。
- データ初期値が 2026-05-24 固定なので、2026-05-27時点では経過時間が75時間以上に見える。
- `renderAnalytics()` の日別チェックインは実データ集計ではなく固定値に近い。
- スマホでは固定下部ナビが表示中コンテンツの下端に重なる場面がある。
- 履歴テーブルはスマホで横スクロール前提だが、状態やメモを読む体験はまだ弱い。
- 空状態、エラー状態、読み込み状態の画面表現が少ない。
- 会話、チャット、通知、呼びかけ、会議室、予定連携、座席予約、管理UIは未実装。

## UI修正の具体メモ

### PC

- オフィスマップは現状かなり見やすい。主役画像として成立している。
- 右のメンバーリストで「76時間45分」のような長い経過時間が出るため、当日運用前提なら `76h` のように短くするか、日跨ぎなら「3日+4時間」表示にする。
- サマリーカードの「最初の入室」はデモデータが古いと不自然なので、日付も併記する。
- 上部の「入退室QR」は実際にはQR表示ダイアログなので、「QRを表示」に近い文言がよい。
- 「リモート中」ボタンが無効状態で淡く見えるが、現在状態なのか操作不能なのか少し分かりづらい。状態バッジと操作ボタンを分離するとよい。
- 左ナビにアイコンを入れると、SaaS画面としてスキャンしやすい。

### スマホ390px

- 1カラム構成は成立している。
- 下部固定ナビがビューポート下端のカードを一部覆うため、セクション間の余白か下部余白をもう少し増やす。
- サマリー4枚が縦に続き、マップまでが遠い。スマホでは2カラムミニカード、または横スクロールのサマリーでもよい。
- 「最初の入室」カードが下部ナビに隠れやすいので、スマホではサマリーから外してもよい。
- メンバー一覧の経過時間が長く、2行になって密度が高い。スマホでは「09:05〜 / 3日4h」など短縮する。
- 履歴はテーブルよりカード形式が読みやすい。
- マップのキャラ詳細はhoverではなくタップで下から詳細シートを出す。

## 推奨実装フェーズ

4. メンバーの状態はどこまで公開するか。全員に見せるか、管理者だけ詳しく見るか。
5. 履歴の保持期間はどれくらいにするか。
6. 個人別の在席時間を出すと監視感が出るため、集計粒度をどうするか。
7. 固定席か自由席か。
8. 予約が必要なのは席、会議室、来客席、リモートブースのどれか。
9. 会議は外部URL連携で十分か、アプリ内音声/映像まで作るか。
10. まず連携したい外部ツールは Google Calendar、Microsoft Teams、Slack、Discord、LINE のどれか。
